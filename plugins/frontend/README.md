# Enigmatry Front-End Skills

Seven reusable Claude skills distilled from the front-end conventions across
Enigmatry projects (EBO Traffic Fleet, Fosim, Enigmatry Back Office, Entry
Blueprint, Entry Angular Building Blocks, Entry Code Generation, Enigmatry
Vacation Planner).

They are **project-neutral**. Everything that was true of only one repo — a
service name, a script name, a Formly migration, a folder path — was pulled out
into a short *Project delta* section at the bottom of each skill telling the
agent what to look up in the repo instead.

Two places where the set deliberately picks a side rather than describing what
exists:

- **`async/await` is the standard async style**, with RxJS reserved for genuine
  multi-value streams. A repo that pipes single values through Observables is
  debt, not a local convention to match.
- **Vitest is the standard test runner.** A repo on Jest, Jasmine or Karma gets
  migrated rather than extended — `angular-testing/references/migrate-to-vitest.md`
  carries the API mapping and the traps.

## The layering

```
frontend-foundations          ← cross-cutting; every other skill points here
├── typescript                ← language delta
│   └── angular               ← framework delta
│       └── angular-testing   ← spec delta (→ references/migrate-to-vitest.md)
├── frontend-styling          ← HTML + SCSS  (→ references/scss-unit-tests.md)
│   └── a11y                  ← what those styles must achieve (WCAG 2.2 AA)
└── frontend-code-review      ← review harness; loads the others by diff type
```

Each skill states its dependency in one line under the heading and carries only
its own delta. Where two overlap, the lower layer wins — a skill may narrow a
rule or name an exception with its reason, never contradict one silently.

**`typescript` is deliberately framework-free** so it can be used on a Node
service or a non-Angular front end. Anything true only because of Angular — the
component model, member visibility, artifact suffixes, lifecycle hooks, RxJS,
forms — lives in `angular`, even where it feels language-shaped.

## Why this split

| Skill | Loads when |
|---|---|
| `frontend:frontend-foundations` | every coding/review task |
| `frontend:typescript` | any `.ts` |
| `frontend:angular` | components, services, templates |
| `frontend:angular-testing` | specs only |
| `frontend:frontend-styling` | `.html` / `.scss` only |
| `frontend:a11y` | user-facing UI |
| `frontend:frontend-code-review` | reviewing a diff |

The token argument for the split: `frontend-foundations` and the language/
framework layer load on almost every task and stay small; `angular-testing`,
`frontend-styling` and `frontend-code-review` only load when the file type or
the task calls for them. A rule lives in exactly one file and the others point
at it, so a change is a one-file edit — the few deliberate restatements (the
`void`-a-promise rule, the generated-code rule) are narrowings that name what
they narrow.

## Installation

```
/plugin marketplace add enigmatry/claude-plugins
/plugin install frontend@enigmatry
```

A back-end-only repo needs none of these skills; an Angular app typically wants
the whole set minus `frontend-code-review` if it already has a project review
skill (disable individual skills per project as needed).

## Keeping project specifics out of them

Put repo-specific facts in the repo — `CLAUDE.md` / `AGENTS.md`, or a thin
project skill that names only the delta:

```markdown
---
name: angular-<project>
description: <project>-specific Angular conventions. Use together with the shared `frontend:angular` skill.
---

# Angular — <project>

> Read the shared `frontend:angular` skill first. This file carries only what differs here.

- Angular 21, classic reactive forms (no Signal Forms yet).
- Notifications: `NotificationService.error()`; HTTP errors handled globally by
  `error.interceptor.ts` — never add a duplicate.
- i18n: `$localize`, extract with `npm run i18n`.
- API client generated by NSwag into `@api`; regenerate with `npm run nswag`.
```

That keeps the shared seven stable and makes a per-project file cheap to read.
